# 专业文档去 AI 味参考 (prd-deslop)

> **时机**:草稿**写完、落档前**的独立回读 pass 用——正文已定,只去表达上的水词/AI 腔,**不动内容**。
> **边界**:本清单管"写得像不像 AI(表达层)";内容对不对、章节全不全归 `prd-review-rubric.md`。
> **适用**:以 PRD 为例,同样适用任何要求严谨无歧义的专业文档(技术方案/规格书/评审纪要);不适用需口语节奏的文案。

## 硬规则(先读,3 条)

1. **规则驱动,不凭感觉**:每处删改必须对得上下面某一条;说不出对应哪条,就别动。
2. **黑名单只在事后审改用,绝不进"生成"指令**。把禁词表塞进写作 prompt 会诱发模型反复提及、反而更常踩(pink-elephant)。所以本文件只在"回读自审"时读,不在起草时加载。
3. **护栏(绝不做)**:
   - 不删任何 load-bearing 内容(字段/需求/约束/验收条件/数字)。分不清是"重复表述"还是"独立需求"→ 保留并标注,不擅删。
   - 不编造统计/引用/口径来"显得具体"。缺口径标"待补",不填假值。
   - 两个高危动作点名禁:(a) 把"没细节但真实的需求"当水词删;(b) 靠编数字把模糊表述具体化("提升性能"→"提升 30%")。

## 怎么扫:先结构后字句,从上往下一遍(顺序不能反)

先修骨架再抠字句——在会被整段删掉的文字上打磨是白费。下面四层就是扫描顺序。

**文档级**(先扫;通用去味工具的盲区,重点):
- **跨节去重**:同一件事在多章节重复 → 合并到一处,其余写"见 §X"。
- **合并镜像章节**:结构对称、内容却空的并列小节 → 合并或删。
- **删出范围内容**:与本期需求无关的铺陈/展望 → 删(删的是范围外叙述,范围声明本身保留)。

**段级**:一段一义;删只有态度没信息的空转总起和"综上所述"式收尾;删与本段结论无关的铺垫。

**句级**(要动句子结构,不是只换同义词——"利用→用"治不了 AI 腔):
- 拆超长无标点句:一句串多件事 → 一句一断言。
- 去名词化:"进行/给予/实现 + 名词" → 直接用动词。反例"进行校验" → 正例"校验"。
- 拆否定对仗:"不是 X 而是 Y" → 直说 Y。
- 空泛断言给口径或删:"大幅/显著提升"无数字 → 补口径或删(不得靠编数字具体化,见护栏)。

**词级**(永远最后,且不能只做词级;下面是示例非穷举,同类照办)扫到即删/换:
- 连接套话:首先、其次、此外、值得注意的是、需要指出的是、综上所述、总而言之。
- 营销形容词:全面、深度、一站式、无缝、强大、卓越、赋能、闭环、抓手。
- false agency:"系统会智能地…/自动为您…" → 只留它实际做什么。
- 凑数空成语与排比:留信息,删修辞。

**重点层**(排版强调,只调"什么顶前、什么加粗",**绝不删/合并任何需求**;PRD 尤其吃重——AI 最典型的病是面面俱到、均匀无侧重):
- **均匀加粗 = 没有加粗**:加粗只给结论句/键名/小标题。整段每条都粗 → 只留真正的主结论粗,其余去粗(反例现象:需求价值一节句句 bold,重点全失)。
- **按优先级排座次,主要展开、次要一句带过**:主要矛盾放前面并展开,次要项下沉、简述。**P0/优先级只认原文或用户显式给的**(含原文/用户已写明的阻塞依赖);原文没给优先级 → **保持原顺序**、需要时标「待确认优先级」,**禁止 AI 自行给需求判 P0/P1、也不自行判定谁阻塞谁**(会改变产品意图,越界)。
- 排座次是调**顺序与强调**,不是删内容——非 P0 需求照写,只是位置靠后。

**格式层**(飞书富文本用得对不对;只在落档前审改,同样不动内容):
- **过度结构化 = 另一种 AI 味**:能一句话/一段说清的,别硬塞表格或多层嵌套列表。语料表格率虽高,但"万物皆表"本身是模板腔。判据:单点结论、线性叙述、轻量小需求 → 段落;组合枚举/多维对照才用表(详见对应域模板的内容→结构/格式决策表)。
- **emoji 克制**:✅❌🟢🟡🔴 只在密集矩阵当值/图例时用(省字、扫读快),别当章节标题装饰或每条前缀撒。
- 加粗/字色/底色/引用块**跟着内容语义走**,不为"显得丰富"堆样式;用了 2 种以上语义色须文首声明图例(与域模板一致),**着色占比核一遍**:量级参照单篇十处上下、长文档约 2~3 处/百块(语料中位数 7 处)——超出量级逐处问"这处颜色对应哪条语义",说不出就去色(具体样式规范见 `lark-cli skills read lark-doc`,别硬编码)。
- **黄底泛滥 = 没重点**(同"均匀加粗=没有加粗"):黄底是无语义的中性强调,整段整节刷黄 → 只留真正要读者停下的那一两处,其余去色。
- **下划线不传义**:语料中下划线无共识语义,读者也读不出你的意图 → 扫到下划线一律换加粗或去掉(易与链接混淆)。
- （流水线内本审改发生在上色前——着色语义与占比的核对由 S9 manifest + S10 lint 负责，本层只审已有的加粗/结构/emoji。）
- **字面值样式收敛**:同一篇里字段名/枚举值一会儿行内代码、一会儿斜体、一会儿下划线 → 收敛成一种(技术字面量→行内代码;用户可见文案→「」),混用=读者需要猜三套记号。

> 本层只管**表达层**(排版、强调、格式),与本文件其余层一致:**不删 load-bearing 内容、不合并需求、不编数字**;拿不准是"重复表述"还是"独立需求"→ 保留并标注。内容对错/章节全不全归 `prd-review-rubric.md`,不在这里打分。

## 改完核(逐条打勾,不认"读顺了")

- 词级清单命中 = 0?
- 字段/需求/约束/验收 逐项还在?(结构那遍最容易误删,重点核)
- 没编造、也没新增任何原文没有的数字/引用/口径?

只认"命中/不命中"这种可核验判断,不认"读起来更自然了"这类语感自评(自己批自己作业会越改越松)。

> 本参考**不追求 burstiness / 句长故意不均**——那是逃 AI 检测、口语化文案要的,PRD 要的是均匀无歧义。别把它当健康分加回,不算句长方差、不做打分表。
