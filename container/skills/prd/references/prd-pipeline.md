# PRD 生产流水线（prd-pipeline）——pm-lite 落档 PRD 的施工单

> **这是工序卡不是参考书**：按工序走，每道工序只读它点名的规则节，别提前读别的（规则只在被执行的工序在场——这是本流水线存在的原因）。
> 命令与格式细节（XML block、白板、图片）以 `lark-cli skills read lark-doc` 为准，别硬编码。

## 落盘与恢复约定（先读）

- 工作目录：`/tmp/prd_work/<slug>/`（slug=需求短名）。**第一件事写 `00_meta.json`**：`{run_id, source_doc_token, source_hash, domain, mode(new|rewrite), lite(true|false), static_change(true|false，纯文案/数值/开关类静态变更才 true——它免除画图)}`——domain/lite/mode 的**唯一权威在 meta**，后续脚本一律读 meta。
- 每道工序产物按编号落盘（见各工序卡）。**每道工序开始前先跑** `python3 <本文件同目录>/gate.py /tmp/prd_work/<slug>/`（同目录=你 Read 到本文件的那个 references/ 目录）——它告诉你当前该做哪道工序；产物已存在则跳过（幂等，中断后从断点续）。**被打断（run_interrupted/超时）后恢复的第一条命令 = 跑 gate.py**，按它的输出续跑，禁止凭记忆重建进度、禁止跳到后段工序。
- 恢复后若距拆图超过 ~30 分钟，重跑图片 fetch 刷新 href（authcode ~1h 时效）。
- **唯一原子发布点 = S10 的一次 `+create`（或改写的 update）**。任何工序不得提前落档。落档后只回读报告，不自动改文档。

## 对用户沟通规范(全工序)

工序卡是给你的施工单,不是给用户的话术。发给用户的每条消息:

- **禁内部术语**:S1-S10 工序号、门①②③、lite/非 lite、manifest、gate/lint、工件文件名——只进工件与日志。反例「S7 对抗自审完成,门③待确认清单如下」→ 正例「初稿写完了,发布前有 3 个问题需要你拍板」。
- **确认清单用编号短句,禁表格**(聊天窄屏里表格挤压难读):每题一行问题+一行默认处理(「不回复则按 X 处理」),让用户能只回一句「都按默认」。
- **不问系统已知的信息**:姓名/身份从会话上下文取(`nine context`/群成员),别让用户自报家门。
- 只有真阻塞的问题才停下来问;能给默认值的按默认继续跑,落档后汇总声明「按默认处理了哪些」。

## 执行环节总览

| 执行环节 | 工序 | 用户参与 |
|---|---|---|
| ① 准备 | S1 定性骨架 → S2 事实查证 | 🚪门①（S1 末复述+假设） |
| ② 写作 | S3 图与范围 → 🛑S3.5 骨架确认 → S4 六章主体 → S5 边界收口 → S6 价值组装 | 🚪门②（S3 末新假设）→ 🛑**S3.5 骨架确认**（发骨架卡停等用户拍板方向，new 非 lite 必停） |
| ③ 回炉 | S7 对抗自审 → S8 deslop | 🚪门③（S7 末待确认清单） |
| ④ 出品 | S9 格式标注 → 脚本上色 → S10 回填图片 → lint → 落档回读 | 无（机器为主） |

**轻量折叠**：S1 判定 lite=true（四条件同时满足：改动点≤2 且单模块 / 无状态机且异常分支≤1 / 触发表全阴性 / 无新概念；任一不满足或拿不准 → 全流程）时：**S3.5 骨架确认全省**（改动点≤2 太小，不值当停下确认；gate/lint 均按 lite 豁免 S3.5 与 H-确认）、S3 仍画小图（**仅纯文案/数值/开关类静态变更才省图**——没有流程可画时硬画是凑数）、S4 退化为极简两段（问题表现/解决方法）、S5 全省（触发全阴性即其合法性证明）、S9 至多一处红底（硬约束级）标注、S7 只跑锚定自查。头部表/版本表/本期不做照留（砍的是仪式，不砍合同要素）。

## 工序卡

### S1 定性骨架（执行①）
- **任务**：判断 ①是不是 PRD 产物（仅存档/纪要 → 跳出本流水线自由叙述） ②新建还是改写——**判据=用户意图不是输入形态**：用户明确要求「更新/补全/改写**这篇已有 PRD**」→ rewrite（S10' 会写回该文档）；用户给的是**需求素材**（MRD/方案讨论稿/会议纪要/原始需求，即使是飞书链接）→ new（素材只作 S2 的事实来源，**绝不往素材文档上写**）。拿不准 → 问用户「是更新这篇文档，还是基于它新建一篇 PRD？」 ③哪个域（交易/履约/nine，判据见 SKILL.md 业务速查+对应 `prd-domain-*.md`「域定位」） ④复杂度（lite 判定见上） ⑤按域章节清单裁剪本篇骨架（A 类必写/B 类按触发/C、D 取舍） ⑥盘素材缺口。
- **读**：读 `prd-core.md` 「适用范围与判定」；读 `prd-core.md` 「骨架机制」；读对应 `prd-domain-*.md` 「域章节清单」。
- **产出**：`00_meta.json` + `01_定位卡.md`（域/类型/lite/骨架清单/缺口/0-3 条假设）。
- **🚪门①**：向用户复述「做什么 / 给谁用 / 核心交互 / 不做什么 / 边界场景」+ 假设清单，等确认再动笔。

### S2 事实查证（执行①）
- **任务**：只查不写。补 S1 缺口：`nine code` 查证/读源码、fetch 源文档、**源文档存在→必须 `+fetch --format json | python3 references/extract_source_images.py <work>` 产 `02_图清单.json`（机械记源图数，是 gate 卡的 S2 必产物 + H-IMG 图丢失门真源；拿「序号:caption」清单见「图片穿透」节）**；每条事实打三标签（已核实/原文复述/未核实推论——查证工具不可用时直接标"未核实推论"，不阻塞）；把代码语言在源头译成业务语言；产六章条件触发判定表（涉存量？资金？跨系统？配置？前端/移动端？）。
- **读**：读 `prd-core.md` 「事实来源透明化」；读 `prd-core.md` 「代码引用边界」。
- **产出**：`02_事实底稿.md`（逐条带标签）+ 触发判定表 + 图片 caption 清单（href 由脚本落 `/tmp/img_hrefs.txt`，不进上下文）。

### S3 图与范围（执行②）
- **任务**：图是思考工具。先静后动：按四触发判要不要产品架构图，再按图类型表选流程/时序/状态机（不默认某一种）；写 mermaid（特殊字符标签一律 `["..."]` 包裹）；每图配一行业务概括引导（禁「见画板」7 字）；**从图上枚举全部菱形分支与状态流转 → 分支总账**；五章范围表同席定稿（3 列表 + 「本期不做」≥2 条）。
- **读**：读 `prd-core.md` 「6.1a 选图决策」；读 `prd-core.md` 「6.1b mermaid 语法与视觉规范」；读对应 `prd-domain-*.md` 「五章范围写法」。
- **产出**：`03_图纸.md`（mermaid 源）+ `03_分支总账.md` + `03_五章表.md`。
- **🚪门②**：新假设抛用户（无新假设可并入门①静默过）。

### S3.5 骨架确认（执行②）
- **任务**：写六章正文（S4，全篇 60% 工作量）**之前**，先给用户一张骨架卡确认方向——方向错在这拦下，省掉后面 60%。**仅 new & 非 lite**（rewrite 走原路、lite 太小均免）。
- **① 写骨架卡** `03_骨架卡.md`（= PRD 章节缩略版，非另编模块，章节对齐域模板）：
  - 一背景 / 二价值 / 三概述：**各一句话**（概述←01_定位卡；价值/背景数据←02_事实底稿）
  - **五 范围**（重点）：做 / 不做——**摘自 03_五章表.md**
  - **六 功能**（重点）：6.1 打算画几个图·各为了表达啥；6.3 拆哪几块·每块一句话意图——**摘自 03_分支总账.md**
  - 四名词 / 七数据复盘 / 八AI审视：一行「会有，按标准写」带过
  - ⚠️ **待确认**：把**所有需用户拍板、且影响后续六章逻辑的点全列**（阈值口径 / 计入时点 / 窗口定义等）——漏了会基于错假设写逻辑导致返工
- **② 发用户等确认**：把骨架卡**当一条消息发给用户**（**无可点按钮**——CCVM 无卡片回调，纯消息），停下；用户在聊天里回「方向对 / 改 X」。
- **③ 记确认** `03_方向确认.md`（≥4 行：用户答复原文 / 确认或调整点 / 时间 / 状态）→ gate 见此文件才放行 S4；调整点须回写到 S4 起将遵循的方向。
- **落档硬门**：H-确认（lint.py）——落档前 03_方向确认.md 缺失/不足 4 行即 RED，借后端「lint 非 GREEN 拒 +create」拦住「**漏了确认这步**（没写确认文件）直接落档」。⚠️ 它只校验确认文件存在且有内容，**不能证明用户真的点了头**——自写假确认文件仍能过（要后端验真人交互才焊得死，本期 follow-up）。所以这门是「确认这步必须发生过」的硬提醒，不是「用户已确认」的保证。
- **读**：本卡即规则（run.py 已喂）。

### S4 六章主体（执行②，全篇 60% 工作量）
- **任务**：对着分支总账逐条落 6.3。**写作三原则**：① 每块内容先过域决策表选形态（该矩阵就矩阵、该一句话就一句话）；② 功能行内容完备=读者能找到触发条件/处理逻辑/返回结果——**这是内容要求不是格式模板，禁止逐行复读「触发：/逻辑：/返回：」加粗标签**（复读=新模板腔），融进自然叙述；③ 多步逻辑/枚举用**真列表分行**（禁 ①②③ 串成段、禁 150+ 字不分行的单元格）。
- **细则**（写到对应内容时看）：矩阵三态先写显式文字（文字是真源，底色是其可视化，禁以色替字）；前台文案一字落地=「」包裹纯文本+`{var}` 单花括号占位+取不到兜底（**禁 `${`**——$ 会被落档解析器当公式吃）；**禁写任何 `<span>`/标记语法**（上色归 S9，见 core「代码引用边界」）；
- **表格形态判定**：表格含 列表分行/单元格底色/内嵌图/自定义列宽/合并单元格 任一 → **整表 XML 写法**（`<table><colgroup><col width>` 定列宽、`<td>` 内可嵌 `<ul><li>`/`<img>`、同域可 rowspan 竖向合并，语法均经落档实测）；纯文字短表 markdown 照旧；说明类长列给宽（col width 参照:窄列 80-120/说明列 300+）。
- **旁注判据**：现状参考/协作待办/口径展开 → 引用块（`>`），别混进正文。其余细则：状态机列全含禁止流转；异常分支「阈值+降级动作+日志」三件套；重复口径立单一真源表按名引用；状态语义/分版**单元格底色直接写 `<td background-color>`**（见「定稿格式裁决」）；图片位置写 `__IMG_N__`（双下划线格式，出品工序机器核残留）。
- **落笔自查**（产出 04 前勾一遍）：□ 无「触发：」式逐行标签 □ 长单元格已列表分行 □ 签名/分版处 td 底色已写 □ 正文零 `<span>`/`<font>` 字面量 □ 零 `${`（占位=单花括号） □ 图片占位全为 `__IMG_N__` □ 旁注已进引用块。
- **读**：读对应 `prd-domain-*.md` 「内容→结构决策表」；读对应 `prd-domain-*.md` 「6.3 功能主体与质量标准」；读 `prd-core.md` 「容器块选用」；读 `prd-core.md` 「代码引用边界」。
- **产出**：`04_六章主体.md` + `04_对账表.md`（五章行 id↔分支 id↔6.3 行「域·模块」复合键 显式映射）。

### S9 格式标注（执行④）
- **任务**：**禁止重发全文**。分块扫描 `08_定稿.md`（每块 ≤80 blocks），对颜色语义表**每一类**输出必答槽位，manifest JSON 契约（apply_format.py 消费，字段名逐字）：
```json
{"slots":[{"category":"红字|绿字|红底|黄底|绿底|蓝底","text":"完整待标注文本(与定稿逐字一致)","occurrence":1,"reason":"一句话语义依据"}],
 "none":[{"category":"...","reason":"该类无适用内容的一句理由"}],
 "undecided":[{"text":"...","reason":"拿不准语义归属"}]}
```
`occurrence`=该 text 在**全文**的第 N 次出现（同文本多处必须逐处一条，各带自己的 occurrence）；每类必须出现在 slots 或 none 之一（整类不许静默跳过）；拿不准的进 undecided（交 lint 报告，不自行刷色）——**undecided 不替代必答**，该类目仍须在 slots/none 给类目级答复。**底色四类（红底/黄底/绿底/蓝底）禁一句"无"带过**：先列候选句（含风险/收益/进行中语义的句子）再决定——确认要上色的才进 slots（候选≠施加，克制量级不因此放松），决定弃权的进 none 且 reason 写扫过的章（如"扫一~八章无风险级内容"）。（单元格底色已在 S4 块级完成，本工序只管行内颜色；行内代码由定稿反引号自足，本工序不再施加。）
- **读**：读 `prd-core.md` 「颜色与容器语义」（含克制三则）。
- **产出**：`09_manifest.json` → 跑 `python3 .../apply_format.py`（机械施加样式+自动图例块+剥样式 hash 对账，唯一允许差异=图例块）→ `09_带样式.xml`。

### S10 lint 与落档（执行④）
- **任务**：**先出图再质检**：若拆图超 ~30 分钟先重 fetch 刷 href → 脚本回填 `__IMG_N__` 为 `<img>` 并**写回 09_带样式.xml**（机械替换，禁手抄 URL；**回填后勿重跑 apply_format**——会从 08 重生成 09 冲掉回填，需改稿=改 08→重跑上色→重回填）→ 跑 `python3 .../lint.py`（硬门红 → 按 violations 的 owning_stage 打回定点修，≤2 轮，仍红则带残留报告征用户意见）→ 绿 → **一次 `+create --doc-format xml`（内容=回填后的 09_带样式.xml）**（改写走「改写变体」的 update 路径）→ fetch 回读自审（逐 `<img>` 核非空 src、白板节点>0、A 类章节在、**6.3 功能主体表未被拆包**、**产出 `<img>` 数≈02 图清单源图数（缺=丢图，见 H-IMG）**——只报告，缺项 💭 提醒用户接力，不自动改档）。**6.3 表拆包核对（飞书偶发把含坏 span 的表 unwrap 成"只剩表头+内容全掉表外散段"）**：回读时核 6.3 表的数据行数是否 ≈ 04 对账表功能点数；若只剩表头行、功能内容变成表外一串 `<p>`/`<ul>` → 判"表被拆包"，💭 报出别放"✅"（lint H18 应已在落档前拦下坏 span，本条是兜底；lite 无对账表/无 6.3 表时跳过，降级只核"6.3 表至少 1 个数据行、非全表头"）。
- **产出**：文档 URL + lint 报告 + 回读核验 + 💭；落档成功后写 `10_published.json`：`{"url":"...","doc_token":"...","published_at":"..."}`（gate 据此判流水线收尾，防中断后重复落档）。

## 改写变体（S1 判 mode=rewrite 时替换对应工序）

用户要改写已有文档时：
- **S2'**：先 `lark-cli docs +fetch --api-version v2` 拿原文**留底**（在工作目录存 `02_原文留底.md`）；对照域章节清单识别缺失/不达标章节（不达标参考：缺关键字段/逻辑跳跃/无数据支撑/边界缺失→建议改写；信息完整但简略→保留）。
- **S4'-S6'**：只写缺失/改写的章节；**A3 契约**：缺失章节在**正文段首**简短说明「AI 新增」；不达标章节改写时在**正文**说明「AI 改写，原内容保留在文档上方，可自行取舍」——**均不写进章节标题**；原文一律保留，让飞书读者分得清哪段是原文哪段是 AI 加的；专有名词按原文，不改写不翻译。
- **S10'**：**原文档原地补全**：`docs +update --command append` 追加缺失章节或改写内容；**版本变更表行不 append**——按「版本变更表协议」用局部精修原位插行（实际执行报错才降级末尾+💭，不许凭猜测提前降级）。或用户选新建文档：复制原文+补全后走 `+create`。
- 原文截图带到新文档：按「图片穿透」节把原图落到**对应功能点位置**，别丢原文截图、别堆末尾。

## 图片穿透（源文档截图带到新文档 · 落到对应位置）

带截图要进单元格时 PRD 用 **DocxXML** 写（markdown 表达不了 cell 内嵌图）。流程：

## 定稿格式裁决（S4-S8 都遵守）

- 草稿正文用 markdown 书写（标题/表格/列表），但**块级富元素直接写 XML 标签**：流程图=`<whiteboard type="mermaid">mermaid源</whiteboard>`、callout=`<callout emoji="📌">…</callout>`、引用容器=blockquote(`>`)、单元格内嵌图=`__IMG_N__` 占位。此混合形态经 `+create --doc-format xml` 落档实测可渲染（2026-07-11 实测 9/9 项：span 行内色/td 底色/callout/whiteboard/表格原生块全部正常，样本 docx AEEJdRuXfoJjDxxo9p3cQNxDnoh）。
- **单元格底色是块级属性，归写作侧**：交易签名的状态语义编码（绿=正常展示/灰=置灰/黄=新增列）与分版底色，S4 写表格时直接写 `<td background-color="…">`（先写文字语义，底色是其可视化；底色用 `light-*` 淡色，如 `light-green`/`light-gray`/`light-yellow`——见 `prd-core.md`「落档色值」）——**S9 只管行内 run 样式，不碰单元格**。
- S9 的行内样式标签语法由 `apply_format.py` 统一施加（`<span text-color/background-color>`），你不手写。

## 落档纪律（唯一真源）

- **交付物 = 飞书文档链接**：落档成功后在 reply 里贴文档 URL 即交付；`/tmp/prd_work/<slug>/` 下的编号工件（`00_meta.json`…`10_published.json`）是内部产物，只供流水线续跑与排错，**不 send-file、不外发**。
- **一次写全再落档**：全部工序完成后一把 `lark-cli docs +create`；不分段多次追加（分段 append 累积噪声、画板/图片错位）。
- **格式判定**：本流水线产物含样式 → **一律整篇 `--doc-format xml`**（「定稿格式裁决」的混合形态正是靠整篇 xml 解析才成立；若误用 `--doc-format markdown`，嵌入的 XML 标签全部失效——这正是历史事故的根因，绝不用 markdown 落档）。
- **表格**由 `docs +create` 原生块生成；**别用通用 markdown 导入器**（表压窄、表头无灰底、mermaid 变代码块）。
- **画图**：§6.1 放白板块；建法先 `lark-cli skills read lark-doc` / `lark-cli skills read lark-whiteboard`。
- **落档后回读自审**：`+fetch` 读回核 A 类章节/白板/图片；漏项 💭 提醒用户接力，**不自动改文档**（白板追加式，自动补会错位/双份）。
- **落档门禁（runtime 强制，非约定）**：VM 的 agent-runner 会在 `docs +create/+update` 执行前核 `10_lint_report.json`，非 GREEN 直接拒绝该命令。被拒后唯一正确动作=跑 gate.py 看缺哪道工序→补齐→lint 绿→重试；别尝试改写命令形式，门禁核的是报告文件本身，改命令只会浪费轮次。
