=== Sub-AC 2.2.3 — Transparent sidecar fallback path ===

Goal
----
Implement a transparent sidecar fallback path that, when the CF signal
is true, re-issues the same request against the host sidecar HTTP
service and returns its response in the same output format as the
agent-browser path, with no manual flag required.

Deliverable
-----------
The fallback path is composed of three modules wired through one
orchestrator entry point:

  container/skills/web-fetch/sidecar_client.py
      should_fallback(primary_envelope, *, env=None) -> (bool, str)
          The auto-detection decision. Fallback fires iff
          primary_envelope["cf_detection"]["is_challenge"] is True.
          NO CLI flag and NO env knob is consulted on the CF path —
          $CF_FALLBACK_ON_PRIMARY_FAILURE is opt-in for non-CF
          failures only and defaults to off.

      fetch_via_sidecar(*, url, method, headers, body, timeout,
                        sidecar_url, fallback_reason, primary_result,
                        opener=None) -> dict
          Re-issues the request against the host sidecar's HTTP /fetch
          endpoint (POST application/json). The request payload
          carries url + headers + timeout — every field is the same
          one that came in to the wrapper.

      _reshape_to_wrapper_envelope(...)
          Translates the sidecar's JSON body into the wrapper's
          canonical envelope shape (same keys as the agent-browser
          path) plus an additive `fallback` diagnostic record.

      _build_unreachable_envelope(...)
          Even when the sidecar can't be reached at all, the returned
          envelope is shape-compatible with the success envelope so
          the agent's parser never special-cases failure.

  container/skills/web-fetch/orchestrator.py
      run_fetch(req, *, primary_runner, sidecar_runner=None, ...)
          Top-level state machine:
            1. Run the primary tier.
            2. Re-tag cf_detection if the primary forgot.
            3. Call should_fallback(); if False → return primary
               envelope.
            4. If True → resolve the sidecar URL, call the sidecar
               runner, re-detect cf_detection on its envelope, and
               return that envelope as the wrapper's response.
          The CLI's --timeout is a TOTAL budget; the orchestrator
          splits it (default 60% primary / 40% sidecar) so a slow
          primary can never starve the fallback.

  container/skills/web-fetch/web_fetch.py
      main(argv) → orchestrator.run_fetch(...)
          The CLI surface (argparse) exposes:
            url, --method, --header, --body, --body-file, --timeout,
            --output, --agent-browser-bin
          Notice the absence of any --use-sidecar / --backend /
          --force-sidecar / --via-sidecar / --cf-bypass switch.
          That absence is the "no manual flag required" clause.

Verbatim AC mapping
-------------------
AC clause                                   │ Implementation site
────────────────────────────────────────────┼──────────────────────────
"when the CF signal is true"                │ sidecar_client.should_fallback
                                            │     branches on
                                            │     cf_detection.is_challenge
                                            │     (no other gate, on the
                                            │      CF path).
"re-issues the same request"                │ orchestrator.run_fetch passes
                                            │     req.url / req.method /
                                            │     req.headers / req.body
                                            │     verbatim into the sidecar
                                            │     runner; sidecar_client.
                                            │     _build_request packs the
                                            │     same url+timeout+headers
                                            │     into the sidecar's POST
                                            │     /fetch body.
"against the host sidecar HTTP service"     │ sidecar_client.resolve_sidecar_url
                                            │     defaults to
                                            │     http://host.docker.internal:8765
                                            │     and the wire request is a
                                            │     plain HTTP POST.
"in the same output format as the           │ sidecar_client.
 agent-browser path"                        │     _reshape_to_wrapper_envelope
                                            │     returns the canonical
                                            │     keyset
                                            │     (ok, backend, status, url,
                                            │      title, html, headers, error,
                                            │      elapsed_s, cf_detection)
                                            │     and only the `backend`
                                            │     value differs; an additive
                                            │     `fallback` diagnostic
                                            │     record records the trail.
"with no manual flag required"              │ web_fetch._parse_args defines
                                            │     ZERO arguments that select
                                            │     a backend. The orchestrator
                                            │     decides; the agent calls
                                            │     ONE command.
